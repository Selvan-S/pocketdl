# PocketDL 0.2.1

## Goal

Make difficult browser-delivered media a first-class source instead of relying on yt-dlp to perfectly reproduce every browser request.

## Capture lifecycle

```text
webRequest.onBeforeRequest
        |
        v
pending request
        |
webRequest.onBeforeSendHeaders
        |
        v
request context enrichment
        |
webRequest.onCompleted
        |
        v
POST /api/captures
        |
        v
SQLite capture history
        |
        v
React capture list
        |
        v
POST /api/captures/{id}/download
        |
        v
QueueService(source_type=captured)
        |
        v
CapturedMediaService
        |
        v
FFmpeg + captured request headers
```

## Why captured media uses a separate downloader path

The browser can successfully fetch a manifest even when yt-dlp's network stack receives HTTP 403 for the same URL. The v0.2 design therefore keeps yt-dlp as the preferred extractor/downloader for normal sources, while browser-captured manifests go directly to FFmpeg with the captured non-sensitive request context.

## Header handling

The capture service rejects and strips `Cookie`, `Authorization`, `Proxy-Authorization` and `Set-Cookie`. This is deliberate. v0.2 proves the browser-capture architecture without creating a credential store.

## Chrome extension constraints

Manifest V3 continues to expose `webRequest` for observing/analyzing requests. Blocking modification is the restricted part of the API. Host permissions are required for the observed request and its initiator.
